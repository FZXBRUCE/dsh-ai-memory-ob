# dsh-ai-memory-ob

> DSH 的长期记忆库插件：把每次对话沉淀成 **Obsidian 库**——记忆条目、用户画像、双链关系图谱。

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](./LICENSE)
![DSH](https://img.shields.io/badge/DSH-%3E%3D0.2.1--rc.2-blue)
![Node](https://img.shields.io/badge/node-%5E22.19%20%7C%7C%20%3E%3D24-brightgreen)

## 它解决什么

和 AI 聊得越久，两个问题越明显：

1. **上下文衰减**——窗口塞满了，早期的决定被挤出去，AI 开始重复问你已经回答过的事。
2. **每轮都写入太贵**——把整段对话反复喂给模型做总结，token 涨得比记忆还快。

这个插件把记忆搬到**对话之外**：写进一个普通的 Markdown 文件夹，用 Obsidian 打开就是图谱。
需要时按需取回一小段，而不是把历史全塞进上下文。

## 快速开始

```bash
# 1. 克隆到本地任意目录
git clone https://github.com/<你的用户名>/dsh-ai-memory-ob.git

# 2. 在 DSH 里安装这个目录（把路径换成你克隆到的位置）
```

然后在 DSH 里让 agent 执行：

```
plugin_manager install_bundle <你克隆到的绝对路径>
```

装好后打开 **设置 → AI 记忆库**，就能看到库路径、状态和全部开关。

## 用 Obsidian 打开记忆库

记忆库本身就是标准的 Obsidian vault：纯 Markdown + YAML frontmatter + `[[双链]]`。
用 Obsidian 打开它，关系图谱、反向链接、搜索全部直接可用，**不需要任何插件或导出**。

### 第一步：确认库在哪

打开 DSH 的 **设置 → AI 记忆库**，页面顶部会显示一行「库路径」，例如：

```
库路径: D:\dsh\ai-memory
```

也可以在设置页的「库文件夹」里改成你想要的位置（支持 `~/path`）。
**这个路径就是下一步要选的文件夹。**

### 第二步：在 Obsidian 里新建仓库

1. 打开 Obsidian，点左下角的 **打开其他仓库**（Open another vault）
2. 选 **创建新仓库**（Create new vault）
3. **仓库名称**随便填，比如 `AI 记忆库`
4. **仓库地址**（Location）→ 点 **浏览**，**选中第一步那个文件夹**

   > ⚠️ 这一步是关键：地址要选到 **库文件夹本身**（`D:\dsh\ai-memory`），
   > 不是它的父目录（`D:\dsh`），也不是某个子目录（`memories`）。
   > 选错了 Obsidian 会显示空仓库。

5. 点 **创建**

如果那个文件夹已经有内容（插件写过记忆了），Obsidian 会直接把它们当成已有笔记加载，
不会覆盖任何东西。想更稳一点，也可以用 **打开文件夹作为仓库**（Open folder as vault）
直接选中同一个目录，效果一样。

### 第三步：看图谱

打开后左侧能看到这些目录：

```
memories/    记忆条目
entities/    实体页（项目/工具/文件）
sessions/    每个对话窗口一页
profile/     用户画像
graph/       图谱索引
zips/        压缩记忆
daily/       每日时间线
```

- **看关系图谱**：左侧栏点图谱图标（或按 `Ctrl+G`），就能看到条目、实体、会话之间的连接
- **从索引进入**：先打开 `graph/graph-index.md`，它按「实体枢纽 → 关系边 → 主题」组织，
  是最推荐的入口
- **看画像**：打开 `profile/user-profile.md`，每个分节都带依据，展开折叠块能看到历史值

### 几个使用建议

**改完不用重新导入。** 插件写文件、Obsidian 读文件，是同一个目录。
新记忆出现后 Obsidian 会自动检测到，图谱随之更新。

**可以直接在 Obsidian 里改。** 画像和条目都能手改，插件下次写入时会合并而不是覆盖。
唯一别改的是 YAML frontmatter 里的 `type` / `title` / `session` 这几个字段，
插件靠它们做索引。

**`.dsh/` 目录不用管。** 那是插件的派生缓存（索引、游标），删了会自动重建，
在 Obsidian 里可以右键选择「排除该文件夹」，免得干扰搜索。

**建议关掉「自动生成唯一标题」。** Obsidian 默认会在重名时加后缀，
但插件靠文件名做双链，改名字会让链接断掉。设置里搜索 "unique" 关掉即可。

### 换库路径怎么办

在设置页把「库文件夹」改成新路径 → 在 Obsidian 里用新路径再建一次仓库。
旧库不会自动搬过去，需要的话手动复制文件夹。

## 会话开关：不想要记忆就不花 token

输入框下方有一个小按钮：**记忆:开 / 记忆:关**。点一下就切换当前会话。

关掉之后：

- 不自动注入记忆（不占上下文）
- 不自动归档（不调模型、不花 token）
- 连轮数都不再计数

但**命令和工具仍然可用** —— 你想手动 `/write` 或 `/load` 随时能调。这是一个
"我这次只想随便聊聊"的开关，而不是把插件卸了。

按钮上的 `*` 表示这个会话被手动覆盖过（不跟随全局默认）。也可以在输入框里用
`/memory on` `/memory off` `/memory reset` 达到同样效果。

全局默认在设置页的「新会话默认启用记忆」里调。

## 七个命令

| 命令 | 作用 |
| --- | --- |
| `/load` | 读取记忆并挂到当前会话上下文。可带日期区间：`/load 2026-10-01..2026-10-20` |
| `/write` | 把本窗口总结后写进库（只写自上次写入以来的新内容）；`/write all` 整窗重写 |
| `/update` | 全量读取库、重建索引，并让模型把条目之间的关系统连成图谱 |
| `/zip` | 压缩成新文件，**源文件不动**。默认本窗口；`/zip vault` 全库；`/zip 2026-10-01..2026-10-20` 区间 |
| `/new` | 新装用户用：扫描历史对话窗口，重建整个记忆库并连好图谱 |
| `/recall` | 按时间线回顾记忆，**不调模型、不花 token**。`/recall 7` 只看最近 7 天 |
| `/memory` | 看/切本会话开关：`/memory` 看状态，`/memory on` / `off` / `reset` |

## 模型工具

| 工具 | 作用 |
| --- | --- |
| `memory_search` | 按关键词 / 日期 / 分类检索，只返回标题与摘要 |
| `memory_recall` | 按路径读一条记忆全文 |
| `memory_write` | 归档本窗（用户说"记住这个"时用） |
| `memory_status` | 看库状态、条目数、当前设置 |

有了这几个工具，AI 可以**主动**查记忆，而不是每次都要你手动 `/load`。

## 库结构

```
<vault>/
├── memories/   记忆条目，一个条目一个文件（原子主张）
├── entities/   实体页：每个项目/工具/文件一页，聚合提到它的记忆
├── sessions/   每个对话窗口一页，串起它的全部条目
├── profile/    用户画像（带证据与历史，可在 Obsidian 里手改）
├── graph/      图谱索引（实体枢纽 + 关系边 + 主题 + 导出的 JSON）
├── zips/       压缩记忆（源文件不动）
├── daily/      每日时间线
└── .dsh/       插件状态（派生缓存，可删）
```

## 记忆长什么样

一条记忆不是"这次对话聊了什么"，而是**一个能独立成立的主张**：

```markdown
---
type: "ai-memory"
kind: "decision"
title: "注入走提示上下文通道"
claim: "记忆注入走框架的提示上下文通道,而不是手工构造消息"
confidence: 0.9
entities: ["dsh-ai-memory-ob", "lib/service.js"]
relates: ["depends-on:记忆库落盘"]
---
# 注入走提示上下文通道

> 记忆注入走框架的提示上下文通道,而不是手工构造消息

## 为什么
手工构造的消息和宿主的消息模型对不上,实测注入不稳定。

## 证据
改造成提示上下文后,/load 在真实会话里立即生效。

## 涉及
- [[dsh-ai-memory-ob]]
- [[lib/service.js]]

## 关联
- 依赖 [[记忆库落盘]]
```

为什么这样切：

- **对话纪要检索不了**。"这次我们聊了命令、设置、目录结构"这种句子主语是"这次对话"，
  以后问"设置项默认值是什么"匹配不上。
- **原子主张可以**。一条一个主语一个结论，能被精确命中，也能被推翻。
- **有了原子性，边才有语义**。能表达"这条推翻那条""这条依赖那条"，
  而不是"这两条都提到了插件"——后者不是关系，是共现。

## 图谱怎么连

图谱有三层，从实体到语义：

| 层 | 是什么 | 例子 |
| --- | --- | --- |
| **实体枢纽** | 被多条记忆提到的具体东西 | `dsh-ai-memory-ob` 被 6 条记忆提到 |
| **关系边** | 条目之间的真实语义关系 | `A --依赖--> B`、`C --取代--> D` |
| **主题** | 模型归的类，给人看的概览 | "记忆注入链路" |

实体页（`entities/`）是真正的连接点：两条记忆指向同一个实体，才有理由被连起来。
`/update` 还会让模型找出**语义重复**的条目并合并，而不是让它们在图谱里并列。

## 用户画像

画像不是"最后一次对话的摘要"。每个分节都带：

- **值** —— 当前结论
- **依据** —— 凭什么这么判断（引用原话或具体行为）
- **自** —— 什么时候观察到的
- **历史值** —— 被推翻的旧值保留在折叠块里，能看到"他变了"

六个分节：身份、沟通风格、工作方式、技术环境、在意的、当前目标。

判断门槛是：**换一个话题还成立吗？** 只对当前任务成立的东西属于记忆条目，不属于画像。


## 设置项

设置页在 **设置 → AI 记忆库**，数据存在 `$DSH_HOME/.dsh-ai-memory-ob.json`
（刻意放在库外：换库路径时设置不会跟着搬走）。

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| 库文件夹 | 空 | 空 = `$DSH_HOME/ai-memory`；支持 `~/path` |
| 自动写入方式 | 每 5 轮 | 或关闭，只用 `/write` |
| 每几次写入 | 5 | 自动写入的轮数间隔 |
| 新会话自动注入记忆 | 开 | 每个新会话首轮自动 `/load` |
| 注入的近期条目数 | 12 | |
| 注入用户画像 / 压缩记忆 | 开 / 关 | |
| 压缩记忆跨窗口共享 | 关 | 关 = 只有压缩它的那个窗口能看到 |
| 注入字符上限 | 4200 | 硬上限，防止记忆挤爆上下文 |
| 单次写入最多条目 | 8 | |
| /new 扫描的会话数 | 8 | |
| 归纳模型 | 空 | `provider/model`；空 = 跟随会话当前模型 |
| 摘要素材带工具名与文件路径 | 开 | 更准，也更费 token |
| 新会话默认启用记忆 | 开 | 关掉后新会话默认不启用，用输入框下方的按钮单独开 |
| 注入时提示"记忆里没有就别猜" | 开 | 减少模型把记忆当万能答案瞎编 |

## 设计取舍

- **记忆是派生缓存**。真相在会话日志里；库随时可以 `/new` 或 `/update` 重建。
  与用户当前的话冲突时，以当前的话为准。
- **注入走框架的提示上下文通道**，不手工构造消息、不往 inbox 塞东西，
  所以不会打断会话流，也不会和宿主的消息模型对不上。
- **子代理不继承用户记忆**：它们的上下文属于父任务，记忆只会干扰判断。
- **写库是增量的**：每条会话有游标，`/write` 只处理游标之后的新事件。
- **整窗重写以窗口为单位替换**：模型换标题也不会在库里留下同义重复。
- **死链过滤**：只写库里真实存在的条目名，Obsidian 图谱里不会出现空节点。
- **压缩件独立**：`/zip` 只新增文件，不改原始条目，所以可以反复压缩、随时回退。
- **会话开关不写盘**：一次性的"这次别记"不该污染全局设置，重启回到默认。
  关掉时连轮数都不计数，所以真的一个 token 都不花。
- **服务用 `ctx.inject` 等就绪**，不用 `ctx.effect` + `ctx.get`：插件激活可能早于
  服务注册，那时 `get` 返回 `undefined` 会永久放弃注册（0.1.1 修的 bug）。

## 更新插件

设置页里有一张 **插件更新** 卡片：

1. 点 **检查更新** —— 从 GitHub 拉 `package.json` 比对版本，只读，不改任何文件
2. 有新版本时会出现 **立即更新** 按钮 —— 调用宿主的插件管理器重新安装
3. 更新后如果界面没变化，**停用再启用插件行**即可加载新代码

卡片上会显示「当前版本 / 远端版本」，以及失败原因（网络、仓库地址缺失、
插件管理器不可用等）。

不想用按钮也可以手动更新：

```bash
cd <插件目录>
git pull
```

然后在 DSH 里停用再启用插件行。

## 兼容性

- 需要 DSH `>= 0.2.1-rc.2`，Node `^22.19 || >=24`。
- 只用宿主已注册的服务，全部按可选取用：缺哪个就少一块能力，不会让整行插件挂掉。
- 不依赖任何第三方运行时库（`node:fs` / `node:path` / `node:os` 而已）。

## 开发

改完宿主代码后，需要停用再启用插件行才会加载新模块：

```
plugin_manager set_plugin include:dsh-ai-memory-ob enabled:false
plugin_manager set_plugin include:dsh-ai-memory-ob enabled:true
```

改 `client.js`（设置页）或 `locale/*.json`（文案）通常热更新即可，刷新页面生效。

### 变更记录

**0.3.0**

重做记忆模型。上一版的根本问题：**条目是对话纪要，图谱是共现关系，画像是最后一次摘要**。

条目：

- 从"一段正文"改成**原子主张**：`claim`（一句话结论）+ `why`（为什么）+ `evidence`（证据）
  + `entities`（具体实体）+ `relates`（带语义的关系）+ `confidence`。
- 提示词硬性要求一条只讲一件事，且 claim 不许出现"这次对话""我们讨论了"这类主语。
- 正文结构固定为 主张 → 为什么 → 证据 → 涉及 → 关联，空节不渲染。

图谱：

- 新增 `entities/` 实体页：每个项目/工具/文件一页，聚合提到它的所有记忆。
  **实体才是连接点**，不是"两条记忆都提到插件所以连起来"。
- 关系边带语义：`supersedes` / `depends-on` / `contradicts` / `refines`，
  渲染成 `A --依赖--> B`，不再是中性的 `↔`。
- `/update` 新增**语义去重**：模型找出"同一个主张说了两遍"的条目并合并，
  保留一条、删掉其余，并在索引里记下合并了什么。
- 图谱索引改为三层：实体枢纽 → 关系边 → 主题。

画像：

- 每个分节带 `value` + `evidence` + `since` + `history`。
- 值变了旧值进 history（能看到"他变了"），值没变只刷新依据。
- 分节从 4 个扩到 6 个：身份、沟通风格、工作方式、技术环境、在意的、当前目标。
- 旧格式分节（概览/偏好/技术栈/目标）在合并时清理，避免两套字段并存。

修复：

- 画像解析把文件头的说明块算进了第一个分节，导致"读回的值 ≠ 写入的值"，
  每次写入都误判成"值变了"，历史里堆满垃圾。现在跳过第一个分节之前的引用块。
- 条目正文渲染用的是未过滤的 `relates`，死链仍会写进 `## 关联`。
  现在渲染过滤后的版本。
- `exportGraph` 还在读旧的 `links` 字段，导出永远是空图。
  现在导出 `relates` + `mentions`（条目→实体）两类边。
- 新增 `test/quality-check.mjs`：用规则判定记忆质量（不许纪要式表达、
  必须有为什么与证据、实体不许是泛词、边必须有类型）。

**0.2.0**

新增：

- **会话级记忆开关**：输入框下方的小按钮，一键决定"这个会话要不要被记忆"。
  关掉后不注入、不归档、不计数，真正零 token；命令与工具仍可手动用。
  也可以在输入框里用 `/memory on` / `off` / `reset`。
- **`/recall` 命令**：按时间线回顾记忆，纯读文件，不调模型、不花 token。
- **`/memory` 命令**：查看或切换本会话开关。
- **记忆时间线**：设置页新增按天分组的条目列表，点标题直接看正文。
- **删除记忆**：`forget` 接口可从库里删掉单条记忆（只允许 `memories/` 下的 `.md`）。
- **设置项**：新会话默认启用记忆、注入时提示"记忆里没有就别猜"。

修复：

- `forget` 的路径校验加固：显式拒绝 `..` 片段，并限制只能删 `.md` 条目文件。
  原先只靠 `startsWith('memories/')` 判断，`memories/../../x` 能穿过第一层检查。
- 服务获取全部改用 `ctx.inject` 等就绪（见 0.1.1），补上遗漏的清理逻辑。

**0.1.1**

- 修复命令与工具静默丢失：原先用 `ctx.effect` + `ctx.get('commands')` 取服务，
  插件激活早于服务注册时取到 `undefined` 就永久放弃注册。改用 `ctx.inject(['commands'], …)`
  等服务就绪后再注册，`tools` / `systemPrompt` / `webServer` 三处同样修正。
- 现象：斜杠命令 `/load` `/write` `/update` `/zip` /`new` 在输入框里不出现、无法调用。
